# 试点部署说明

## 上线前

- 只纳入已确认可通过 Android 系统目录选择器读取通话录音的机型。
- 每台手机登记销售手机号（11 位纯数字）和设备名称，例如“张三”。手机号用于统一命名，不使用 IMEI 等硬件隐私标识。
- 上传文件名中的时间取录音文件名里的录音时间；未匹配到厂商文件名格式时，回退为文件最后修改时间，绝不使用同步发生时间。试点时应记录每款手机的录音文件名样例并补充适配规则。
- 确认员工已知悉录音会同步至指定 MacBook，明确访问人员和保存期限。
- MacBook 的共享目录只开放给专用账号；质检脚本读取正式 `.mp3` 文件，忽略 `.uploading` 文件。

## 验收

1. 新增一段 MP3 录音后，点击“立即同步”。
2. 共享目录出现 `手机号_yyyyMMddHHmmss.原始扩展名.uploading`，完成后只保留同名正式音频文件；若关闭统一命名，则保留原文件名。
3. 正式文件大小与手机源文件一致，App 显示“UPLOADED”。
4. 断开网络或关闭 MacBook 后触发同步，App 显示失败；恢复条件后 WorkManager 自动重试或点击“立即同步”重试。

## 已知边界

- 本项目不限制文件扩展名、不转码；所选目录第一层的所有普通文件均按原格式上传。
- Android 系统后台任务并非精确闹钟，02:00 是最早执行窗口，可能因省电策略延后。
- 手机号与时间精确到秒；如同一手机同一秒产生两份录音，第二份会保留在失败队列，需人工处理，避免重命名规则冲突。
